# OKF discovery and agent instructions

Research accessed 2026-10-04. GitHub files were read with `gh api`. Repository links below pin the inspected revisions where available.

## What v0.2 specifies

Google's OKF v0.2 does not require a bundle-root `index.md`, define a `README.md` role, or give a general bundle-discovery and task-retrieval procedure. A bundle is a directory of Markdown files; `index.md` may appear at any level, including the root. An index lists that directory's contents to support progressive disclosure. Producers may generate indexes, and consumers may synthesize one when absent. A root index may contain `okf_version: "0.2"`; this is version metadata, not an agent entry-point declaration. The spec also excludes prescribing serving or query infrastructure. See [bundle structure and reserved files](https://github.com/GoogleCloudPlatform/open-knowledge-format/blob/ad30107c31c06aec8a7d5636e0d1058118604e6f/SPEC.md#L105) and [index files](https://github.com/GoogleCloudPlatform/open-knowledge-format/blob/ad30107c31c06aec8a7d5636e0d1058118604e6f/SPEC.md#L505).

The spec offers content conventions that can help retrieval: concept `type`, `title`, `description`, and `tags`; sectioned Markdown; descriptions in index entries; and links between concepts. It leaves general task retrieval to the consumer. Section 10.5 gives informative discovery, loading and execution guidance specifically for Attested Computations. The `index.md` progressive-disclosure language is a recommendation about browsing, not a contract that every agent will discover or read an index.

Google's [reference agent](https://github.com/GoogleCloudPlatform/open-knowledge-format/blob/ad30107c31c06aec8a7d5636e0d1058118604e6f/src/reference_agent/prompts/reference_instruction.md) is a producer. Its prompt reads existing concepts and lists available concepts to write links; it does not implement a general query-time consumer. The repository calls its viewer a proof-of-concept consumer. Google Cloud's [Knowledge Catalog integration](https://cloud.google.com/blog/products/data-analytics/scale-okf-bundles-across-an-organization-with-knowledge-catalog) describes a governed searchable service with search and context-retrieval APIs, which are consumer-side infrastructure beyond the file format.

## How projects teach agents to use a bundle

The examples I found add discovery instructions outside the OKF bundle, using a native Skill, `AGENTS.md`, or MCP configuration. These are concrete integration patterns, not requirements of v0.2.

- The [serradura/okf skill](https://github.com/serradura/okf/blob/cfb7ffac7fef37d56e97b5b7dd8fe97ffc648c7c/gems/okf/lib/okf/skill/SKILL.md) routes task intent to a consume or search playbook. Its [consume playbook](https://github.com/serradura/okf/blob/cfb7ffac7fef37d56e97b5b7dd8fe97ffc648c7c/gems/okf/lib/okf/skill/playbooks/consume.md) says to orient with the bundle map and index, follow needed links, or use a map-search-read flow for a pointed question. Its [root AGENTS.md](https://github.com/serradura/okf/blob/cfb7ffac7fef37d56e97b5b7dd8fe97ffc648c7c/AGENTS.md) names the knowledge bundle for each code area and gives an `okf search` route. The README says the skill can be installed for agents without the gem, while the CLI is an optional retrieval mechanism.
- The [Crossplane v2 OKF skill](https://github.com/jkroepke/okf-crossplane-v2/blob/15c708624a0a017be48a80ca690c76f3adac2fd5/skills/crossplane-v2-okf/SKILL.md) makes its MCP bundle the exclusive external source for a defined technical domain. It tells the agent to list bundles, request focused context, then search and fetch exact concepts; for a Composition task it points first to a named starter concept and follows its links. The repository's [AGENTS.md](https://github.com/jkroepke/okf-crossplane-v2/blob/15c708624a0a017be48a80ca690c76f3adac2fd5/AGENTS.md) identifies repository-wide restrictions and points at shared workflows and specialist roles. This is the clearest example of project instructions making retrieval happen before coding, but it is MCP-specific and has no published controlled outcome evaluation.
- [Pi LLM Wiki's skill](https://github.com/zosmaai/pi-llm-wiki/blob/9bb4daa4105f0f58b23c5957671437160acda9c6/skills/llm-wiki/SKILL.md) asks the agent to call recall at task start, read returned pages, and save durable findings at task end. Its README describes personal and project vault recall. This illustrates a runtime-triggered pattern for a Markdown wiki with OKF support, but it is not a rule from OKF and the skill's own wiki tools mediate retrieval.

## Outcome evidence and limits

The strongest nearby coding-agent evidence is [ContextBench](https://arxiv.org/abs/2602.05892), submitted February 5, 2026. It evaluates 1,136 issue-resolution tasks across 66 repositories and eight languages, using human-annotated relevant context and agent trajectories. It measures context recall, precision, efficiency, and whether explored context was used. The paper reports marginal retrieval gains from more elaborate agent scaffolding, a tendency toward recall over precision, and a gap between context explored and context used. It does not test OKF bundles or personal memories, and its abstract does not establish that one instruction layout improves final patch success.

[Agent Retrieval Bench](https://arxiv.org/abs/2607.24882), submitted July 27, 2026, compares file retrieval methods across 427 coding-workflow examples and records agent context acquisition. Its authors report that no retrieval family wins across tasks, and that observed agent trajectories miss all gold files in 27–35% of samples. Its measures concern file retrieval under token limits, not use of OKF or whether retrieved information was correctly applied in a patch.

These sources establish that retrieval and context use are measured problems in coding agents. They do not establish that an optional OKF root index is discovered automatically, that reading it leads to better coding outcomes, or that a particular Skill/`AGENTS.md` instruction saves tokens. Measure those outcomes directly against the same task set and memory snapshot.
