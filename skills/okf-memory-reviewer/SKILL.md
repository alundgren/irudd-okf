# Memory reviewer

Run context and bundle inspect, then discover change read and change review with
cli search and cli schema. Read the exact proposal, accepted baseline and every
recorded source revision. Assess applicability, conflicts, evidence and procedure
changes. Accept routine work, such as consolidation, deduplication, added evidence,
stage changes and archiving, when the evidence supports it. The author may also
review routine work; do not impose another review layer. Record your own agent
identity and reason. If the user already explicitly approved a concrete scope,
carry that decision through matching implementation with `change review`'s
`approval` reference, scope and exact path/revision list. Never declare a human
actor or claim they reviewed generated bytes. Core still rejects stale revisions,
changed evidence and revisions outside that list. The agent must check semantic
fit to the approved scope; substantive deviations and unresolved judgments stay
pending for a new decision about the difference only.
